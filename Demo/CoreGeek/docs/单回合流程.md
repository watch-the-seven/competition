# 单回合完整处理流程

本文说明程序**收到一个 Request 到发出一个 Response 之间，每一步做了什么、为什么这么做**。
所有代码引用都用 `文件:函数()` 标注（行号会随版本漂移，故不写死）。

## 总览

```
判题器 ──POST──▶ ① 收字节 ──▶ ② 解析 ──▶ ③ 记请求日志
                                              │
                        ┌─────────────────────┘
                        ▼
              ④ decide()  ← 决策总入口（全程持锁）
                   ├─ 4.1 Turn.load       报文 → 强类型
                   ├─ 4.2 MEMORY.begin    开局初始化 + 复盘上一回合
                   ├─ 4.3 _day / _night   按昼夜算出指令
                   └─ 4.4 MEMORY.remember 记下本回合指令
                        │
                        ▼
              ⑤ 序列化（只做一次）──▶ ⑥ 记响应日志 ──▶ ⑦ 发送
                                                          │
判题器 ◀──── HTTP 200 + JSON ─────────────────────────────┘
   └─ 下一回合把 llmResp / lastCmdResult / phaseTask / 动作合法性带回 → 回到 ①
```

---

## 阶段 0：进程启动（整局只发生一次）

`run.sh` → `main3.py:main()`

```python
if len(sys.argv) != 2:
    raise SystemExit("Usage: python main3.py <port>")
port = int(sys.argv[1])
root = Path(__file__).resolve().parent
os.chdir(root)                          # ① 固定工作目录
sys.path.insert(0, str(root / "src"))   # ② 让 agent 包可导入
logging.basicConfig(stream=sys.stdout, level=logging.INFO,
                    format="%(asctime)s | %(message)s")
from agent.server import serve          # ③ 延迟导入
serve(port)                             # ④ 阻塞
```

**为什么这么做**

- 判题器可能在任意目录把我们拉起来，`chdir` 保证相对路径与导入不受调用方目录影响；
- `basicConfig` 必须在导入 `agent.server` 之前调用，否则各模块的 `LOGGER` 已建立、格式不再生效；
- `serve()` 内部是 `serve_forever()`，会一直阻塞；之后每回合都由 HTTP 回调驱动。

`server.py:serve()` 使用 `ThreadingHTTPServer`（每连接一线程）——**这是阶段 4 必须加锁的根本原因**。

---

## 阶段 1：收字节

`server.py:Handler.do_POST()`

```python
length = int(self.headers.get("Content-Length") or 0)
raw = self.rfile.read(length)
```

**为什么按 `Content-Length` 读而不是读到 EOF**：HTTP/1.1 支持长连接，同一 socket 上会连续来多个请求，**没有 EOF 可以等**。不按长度读就会多读或阻塞，也就是粘包。

---

## 阶段 2：解析与容错

```python
try:
    text = raw.decode("utf-8")
    payload = json.loads(text)
except Exception:
    LOGGER.exception("请求体不是合法 JSON：%r", raw[:RAW_LOG_LIMIT])
    self._send(json.dumps(empty_response(), ensure_ascii=False).encode("utf-8"))
    return
```

**为什么单独一个 try**：报文是外部输入，解析失败不是我们的 bug，但**仍然必须回一个合法响应**——接口文档第 8 章规定累计 5 次异常即停止调度该队，卡住或崩溃等于自杀。这条路径下正常日志记不了，于是退化为记录原始字节前若干字节。

---

## 阶段 3：请求入日志

`server.py:_log_round()`

日志是**机械**的：收到的原文与即将发出的字节原样写入，中间用分界线隔开。

```
────────────── round 41 ──────────────
>>> REQUEST
{"roundNo": 41, "mapInfo": {...}, "teamOur": {...}}
<<< RESPONSE
{"roleCommandMap": {...}, "prompt": "", "executeCmd": ""}
──────────────────────────────────────
```

详细度由 `server.LOG_VERBOSITY` 控制，可用环境变量 `AGENT_LOG_VERBOSITY` 覆盖：

| 模式 | 一整天(130 回合)实测 | 说明 |
| --- | --- | --- |
| `full`（默认） | 约 562 KB | 原样写入 Request 与 Response |
| `digest` | 约 145 KB | 只记关键字段（**非原样**） |
| `off` | 约 0.4 KB | 只有启动与告警 |

## 阶段 4：`decide()` —— 决策总入口

`brain.py:decide()`

```python
def decide(payload):
    turn = Turn.load(payload)               # 4.1
    with MEMORY.lock:                       # ← 全程持锁
        if MEMORY.last_round == 0:
            _log_roster(turn)               # 整局只打一次
        MEMORY.begin(turn)                  # 4.2
        response = empty_response()         # 默认「不下任何指令」
        if turn.is_day:
            _day(turn, response)            # 4.3
        else:
            _night(turn, response)
        MEMORY.remember(response["roleCommandMap"], turn)   # 4.4
        return response
```

**为什么持锁**：`ThreadingHTTPServer` 每连接一线程，而 `MEMORY` 是跨回合共享的模块级单例。
没有锁，两个请求可能同时读写 `plan` / `task.phase` / `boss` 等状态而撕裂。
用 `RLock` 而非 `Lock`，因为内部函数可能再次进入同一把锁。

**为什么默认空响应**：`empty_response()` 就是「本回合什么都不做」的合法报文。
任何分支漏填，结果依然合法，不会产出畸形报文。

### 4.1 `Turn.load` —— 报文 → 强类型

`protocol.py:Turn.load()`

```python
round_no = as_int(payload.get("roundNo"), 1)      # 缺字段也不炸
info  = payload.get("mapInfo") or {}
team  = payload.get("teamOur") or {}
...
return cls(
    round_no=round_no,
    is_day=(round_no - 1) % ROUNDS_PER_DAY < DAY_ROUNDS,   # ← 昼夜唯一判定处
    gold=as_int(team.get("goldNum")),
    zones={Pos.load(z["pos"]): as_kind(z.get("neutralType"))
           for z in info.get("zones") or ()},
    ours=tuple(Unit.load(r) for r in team.get("roles") or ()),
    ...
)
```

**为什么集中在解析层**：策略层要写大量「这个单位是不是工人」「这格是不是矿」的判断。
若每条都去 `payload[...][...]` 里掏并判 `None`，策略代码会被噪音淹没。
于是把**类型转换、坐标换算、缺字段兜底**全部压进 `Turn.load`，策略层只面对强类型对象。

三个具体坑：

- `roundNo` 缺失时 `as_int(..., 1)` 兜底；
- `lastRoundRoleActionResults` 的键在 JSON 里是字符串，统一转回 `int`；
- `weaponShop` 这类驼峰枚举用 `as_kind()` 映回规范拼写——直接 `.lower()` 会得到
  `weaponshop`，导致商店永远匹配不上（这个坑实际踩过）。

### 4.2 `MEMORY.begin` —— 开局初始化 + 复盘上一回合

`memory.py:Memory.begin()`

```python
if self.plan is None:
    self.plan = Plan.build(turn)                 # 只在第一回合算一次
if self.plan is not None and self.stone_worker is None:
    self._assign_roles(turn)                     # 分工与站位，只分一次

if not self.task_points and turn.player_tasks:   # 任务点晚下发也能补上
    self.task_points = [task.pos for task in turn.player_tasks]

for role_id, ok in turn.action_results.items():  # 复盘上一回合
    if ok:
        self.blocked_step.pop(role_id, None)
        continue
    command = self.issued.get(role_id)
    ...
    if action == "build" and target is not None:
        self.bad_build.add(target)               # 建造被拒 → 拉黑该格
    elif action == "move" and target is not None:
        self.blocked_step[role_id] = target      # 移动被挡 → 记住落点
```

**为什么需要复盘**：判题器**只告诉你「这条指令合法/非法」，不告诉你为什么**。
程序必须自己把「上回合发了什么」（`issued`）与「判题器说它不合法」对照起来推断原因。
这是自适应能力的基础：

- 建造非法 → 多半是该格不在可建造区 → 记进 `bad_build`，以后不再试（即"试探"机制）；
- 移动非法 → 多半是碰撞 → 记进 `blocked_step`，下回合优先绕开。

**为什么布局只算一次**：基地整局不动，布局是静态的；每回合重算纯属浪费，还引入漂移风险。

### 4.3 昼夜分派

#### 白天 `_day()`

`brain.py:_day()`

```python
commands = response["roleCommandMap"]
claimed: set[Pos] = set()          # 本回合已被预定的格子
jobs = _assign_jobs(turn)          # 每个角色一个岗位
for role in turn.controllable():
    job = jobs.get(role.unit_id, "hold")
    if job == "task":   _task_step(...)
    elif job == "boss": _boss_step(...)
    ...
```

**为什么分两层（先 `_assign_jobs` 再逐个执行）**：分工之间会争抢同一个角色
（归位 > BOSS 采购 > 常规分工）。必须先**全局**确定谁干什么，再逐角色产出指令；
否则后面的角色看不到前面已占用了谁。

**为什么有 `claimed`**：三人在同一回合各自做 A* 规划，可能选中同一个格子。
`claimed` 记录「本回合已被预定」，`_advance()` 会跳过它，避免自家两人对撞浪费回合。

岗位清单：

| 岗位 | 含义 |
| --- | --- |
| `return` / `sell` | 时间不够，回防（顺路把矿卖掉） |
| `boss` | 去武器商店门口等/买/用 BOSS 召唤令 |
| `task` | 开拓者做自进化任务 |
| `towers` | 造火箭发射台 |
| `stone` / `walls` | 采石 / 砌墙 |
| `ore` | 采矿卖钱 |

#### 夜晚 `_night()`

`brain.py:_night()`

```python
threats = _threats(turn)                     # 只打「冲我们来的」
priority = _priority_robot(turn, threats)    # 其中离我方基地最近的
virtual_hp = {r.robot_id: r.health ...}      # 虚拟血量池

# ① 给每个角色配一座武器（已贴着且不在冷却的优先，其次回专属武器位）
# ② 能开火的先开火：射程内有威胁就打，cell 为 None 才不开
# ③ 没开火的角色朝自己的武器靠拢
```

**为什么先配对再开火**：一个角色只能同时操控一座武器（接口文档 2.2），
必须保证「角色 ↔ 武器」一对一；`used` 集合防止两人抢同一座塔。

**为什么要虚拟血量池**：三座塔按顺序决策。若各自独立计算，可能三发都打同一台残血机器人，
后两发全部浪费。`_apply_blast()` 每决定一发就从池里扣减，后续的塔看到的是
「已被计划击杀后」的血量，会自动改打别的目标。

### 4.4 `MEMORY.remember` —— 留证据

`memory.py:Memory.remember()`

```python
self.issued = {int(key): value for key, value in commands.items()}
self.issued_round = turn.round_no
```

这就是下一回合 `begin()` 用来复盘的「我上回合发了什么」。
没有它，`lastRoundRoleActionResults` 里的 `false` 只是一堆无意义的布尔值。

> 细节：`roleCommandMap` 内部键是 `int`，`json.dumps` 时才变成字符串，
> 所以这里要 `int(key)` 转回来。

## 阶段 5～7：序列化 → 记日志 → 发送

`server.py:Handler.do_POST()` / `_send()`

```python
# 只序列化这一次：记进日志的就是马上要发出去的那串字节。
body = json.dumps(response, ensure_ascii=False).encode("utf-8")
if LOG_VERBOSITY != "off":
    _log_round(payload, text, body)
self._send(body)

def _send(self, body: bytes) -> None:
    self.send_response(200)
    self.send_header("Content-Type", "application/json; charset=utf-8")
    self.send_header("Content-Length", str(len(body)))
    self.end_headers()
    self.wfile.write(body)
```

**为什么只序列化一次**：若日志与发送各 `json.dumps` 一次，二者可能因参数不同而不一致，
「日志里看到的」就不再等于「实际发出去的」。现在同一个 bytes 既进日志又上线，
**日志与链路逐字节一致**（已用重复键 / `\uXXXX` 转义 / 浮点的报文验证过）。

**为什么显式给 `Content-Length`**：客户端依赖它判断报文结束。

## 阶段 8：闭环 —— 本回合输出决定下回合输入

| 请求字段 | 由谁产生 | 用在哪里 |
| --- | --- | --- |
| `lastRoundRoleActionResults` | 上回合的 `roleCommandMap` | `begin()` 推断 `bad_build` / `blocked_step` |
| `llmResp` | 上回合顶层 `prompt` | `_handle_llm()` 解析 `CMD:` / `ANSWER:` |
| `lastCmdResult` | 上回合顶层 `executeCmd` | 回灌进新的 prompt |
| `phaseTask` | 上回合 `acceptTask` | 交给 LLM 解题；变空表示任务结束 |

所以「收请求 → 发响应」不是孤立循环，而是多位一体的跨回合问答：

```
第 N   回合：发 prompt          →  第 N+1 回合：收到 llmResp
第 N+1 回合：发 executeCmd     →  第 N+2 回合：收到 lastCmdResult
第 N+2 回合：把输出回灌再问      →  第 N+3 回合：收到 ANSWER
第 N+3 回合：submitAnswer      →  第 N+4 回合：phaseTask 变空 → 任务结束
```

## 全链路小结

| # | 阶段 | 代码位置 | 为什么 |
| --- | --- | --- | --- |
| 0 | 启动、建监听 | `main3.py:main()` / `server.py:serve()` | 固定目录与导入；多线程服务 |
| 1 | 按长度读字节 | `server.py:do_POST()` | 长连接没有 EOF |
| 2 | 解析 + 容错 | `server.py:do_POST()` | 外部输入；异常也要回合法响应而非崩溃 |
| 3 | 请求入日志 | `server.py:_log_round()` | 崩了也知道输入是什么；原样不加工 |
| 4.1 | 报文 → 强类型 | `protocol.py:Turn.load()` | 把类型转换与兜底挡在策略层之外 |
| 4.2 | 初始化 + 复盘 | `memory.py:Memory.begin()` | 判题器只说合法/非法，原因得自己推 |
| 4.3 | 昼夜分派 | `brain.py:_day()` / `_night()` | 白天建造采集做任务，夜晚操控武器 |
| 4.4 | 记录指令 | `memory.py:Memory.remember()` | 供下回合复盘 |
| 5 | 序列化一次 | `server.py:do_POST()` | 保证日志 == 链路字节 |
| 6 | 显式长度发送 | `server.py:_send()` | 客户端才能正确读完 |
| 7 | 判题器回带结果 | 下一回合的 Request | 形成跨回合闭环 |

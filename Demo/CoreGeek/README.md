# CoreGeek —— 第一天（前 130 回合）解题说明

判题器通过 HTTP 下发每个回合的地图状态，本程序返回该回合的动作。
本解题只针对**第一天**：白天 70 回合 + 黑夜 60 回合。

## 运行

```bash
bash run.sh <port>               # 接口文档第 1 章的样例启动方式
python3 main3.py <port>          # 等价写法：监听 0.0.0.0:<port>，POST 任意路径即一次决策
python3 tools/smoke.py           # 离线迷你裁判器（进程内直调 decide），跑满 130 回合断言需求
python3 tools/mock_judge.py      # HTTP 级联调：把本程序当独立进程拉起来，走真实 socket 驱动 130 回合
```

响应固定为 `{"roleCommandMap": {...}, "prompt": "...", "executeCmd": "..."}`。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `run.sh` | 判题器启动入口（`bash run.sh <port>`） |
| `main3.py` | 命令行入口：校验端口、切换工作目录、加载 `agent.server` |
| `src/agent/protocol.py` | 解析 Request（含 `playerTasks` / `vendorShopList` / `llmResp` / `lastCmdResult` / 动作合法性），构造全部动作码 |
| `src/agent/grid.py` | 八方向栅格 A*：多目标寻路 + 路径长度估计 |
| `src/agent/memory.py` | 跨回合记忆；开局一次性算出基地几何布局（C 形护罩 / 3 个火箭位 / 3 个站位） |
| `src/agent/brain.py` | 策略本体：白天分工、自进化任务状态机、BOSS 采购、夜晚集火 |
| `src/agent/server.py` | `ThreadingHTTPServer`；任何异常都回空指令，保证进程不被打死 |
| `tools/smoke.py` | 迷你裁判器 + 断言（进程内调用策略） |
| `tools/mock_judge.py` | HTTP 级联调：真实进程 + 真实 POST，逐条校验接口文档并测时延 |

## 建造区假设（按需求确认）

基地是 2×2，报文里的 `pos` 是左上角：

- **基地外一圈**（与 2×2 外形的切比雪夫距离 = 1，共 12 格）＝ 蓝色**武器**可建造区；
- **再外一圈**（距离 = 2，共 20 格）＝ 黄色**城墙**可建造区。

代码按这个规则选址，并且保留探测兜底：某格建造被 `lastRoundRoleActionResults`
判为非法时，该格进入 `Memory.bad_build` 黑名单，之后改选其它格子。

## 白天分工（按角色）

1. **工人 A —— 10 石 + 10 墙**
   - 到最近的石矿采 **10** 块石头（每回合 1 块）；
   - 回基地按 **C 形护罩**砌 10 面墙：朝敌一侧竖排 6 格，顶行/底行各再向内延伸 2 格，
     背向敌人的一侧留开口（左上角基地封右侧，右下角基地封左侧）；
   - 砌完就去采最近的铜/铁矿并卖给小贩。
2. **工人 B —— 3 座火箭发射台**
   - 开局的 75 金刚好够 3 × 25，先建满 3 座火箭；
   - 然后去采铜/铁矿并卖给小贩。
3. **开拓者 —— 2 个自进化任务**
   - `acceptTask` 领任务（全程站在任务点 1 格内，否则任务作废）；
   - 把任务原文交给 `prompt`（LLM），按回复决定是 `executeCmd` 进沙盒跑命令，
     还是 `submitAnswer` 交答案；命令输出会回灌给 LLM 继续推理；
   - LLM 轮次用尽时，把沙盒最后的输出兜底提交，绝不让任务空转到超时；
   - 任务做完回火箭旁待命。
4. **BOSS 召唤令**
   - 金币一旦 ≥ 200（价格从 `weaponShopList` 动态读取），离武器商店最近、
     且来得及在入夜前完成的角色去买，下一回合立刻 `use`。

### 采矿的时间预算

`_pick_mine` 不会选「跑不完的矿」：一次完整循环
（走到矿 → 采 N 块 → 走到小贩 → 卖 → 走回火箭旁）必须能在第 68 回合前收尾，
否则降低 N（少采几块）或直接放弃。这避免了「背着一整包矿被归位截止时间打断、
最后一分钱没卖出去」的情况。

## 夜晚（第 71~130 回合）

- 三个角色各守一座火箭；开火要求角色与武器相邻、武器不在冷却（火箭冷却 3 回合）。
- **目标是离我方基地最近的机器人**，不是离敌方基地最近的。
- 落点按火箭伤害模型取单回合最大伤害：中心 20、周围 8 格各 10；
  用「虚拟血量池」按火箭顺序结算，避免同一只机器人被重复计算溢出伤害，
  并对「最靠近我方基地的那台」加权，兼顾集火与最大化输出。
- 打散兵很亏（要等 3 回合冷却），所以只有一轮齐射能打出 ≥ 2 只机器人的伤害、
  或敌人已逼近基地时才开火。

## 可调参数（`src/agent/brain.py` 顶部）

| 常量 | 默认 | 含义 |
| --- | --- | --- |
| `SELL_BATCH` | 20 | 一趟最多背多少矿石去卖（≈「采两个矿」） |
| `MIN_YIELD` | 3 | 少于 3 块就不值得专门跑一趟 |
| `MAX_CHAIN_LEG` | 8 | 背着货时只顺路再采更近的矿 |
| `ORE_DEADLINE` | 68 | 一趟采矿循环最晚收尾回合 |
| `RETURN_SLACK` | 1 | 归位预留回合数 |
| `BOSS_USE_DEADLINE` | 68 | 购买 + 使用 BOSS 令的最晚回合 |
| `TASK_LLM_MAX` / `TASK_CMD_MAX` | 6 / 4 | 单个任务的 LLM 往返 / 沙盒执行上限 |
| `FIRE_MIN_VALUE` | 40 | 一轮齐射的最低期望伤害 |
| `URGENT_BASE_DISTANCE` | 9 | 敌人逼近到这个距离就无条件开火 |

## 自测覆盖

`tools/smoke.py` 用 `docs/request.txt` 的地图搭了一个迷你裁判器（含矿井刷新、
小贩收购、商店价格、机器人夜晚推进、任务下发与 LLM 回复），四个场景全绿：

| 场景 | 校验点 |
| --- | --- |
| 样例矿价 + 任务 160 金 | 3 火箭 / 10 墙 / 2 任务 / 三人就位 / 金币过 200 并买用 BOSS 令 / 夜晚开火有效 |
| 高矿价 copper=25 | 矿价波动时同样走通整条链路 |
| 任务奖励低 (30/个) | 结构目标仍全达成，只是买不起 BOSS 令 |
| LLM 不作答 | 轮次用尽会兜底提交，2 个任务不白做 |

`tools/mock_judge.py` 进一步做 HTTP 级联调：用 `bash run.sh <port>` 把程序拉起成独立进程，
通过真实 socket 逐回合 POST，并校验——

- 传输层：建连耗时 < 10s、单回合响应 < 5s（接口文档第 8 章）；
- 报文层：顶层 `roleCommandMap`/`prompt`/`executeCmd` 齐全、动作码合法、必填字段齐全、
  `targetPos` 为 `{x,y}` 数组、`controllerId` 为字符串、`num` 为整数、
  多目标武器的落点数等于当前等级；
- 语义层：指令指向的角色必须存在、操控者必须紧贴武器、`executeCmd` 只在任务期间下发；
- 健壮性：非法 JSON / 空对象 / 非根路径 POST 都不会让进程崩溃。

最近一次运行结果：130/130 回合完成，单回合往返平均 1.4ms、最大 12ms，
0 条协议错误、0 条语义告警，支持 keep-alive，进程全程存活。

## 已知边界

- **200 金够不够，取决于任务奖励。** 两个自进化任务按实际报文约给 160 金，此时
  样例收购价（石头 1 / 铁 3 / 铜 5）下也够用：初始 75 − 建塔 75 + 任务 160 + 一轮卖矿，
  第 40 回合金币过 200，第 46 回合买入、第 47 回合使用 BOSS 令。
  只有任务奖励也很低时（例如 `docs/request.txt` 字面写的 30/个）才凑不齐——
  那种局面下 70 回合的采矿上限约 110~140 金，代码会转为「尽量多赚、够了立刻买」，
  买不起就留作余额。若你希望此时改买武器升级券（100+150），说一声我加 fallback 分支。
- **BOSS 召唤令按任务书 4.6.3 是给对方加怪**（`对方下个夜晚 BOSS 机器人个数 +1`），
  不是给自己加。这里按需求照买照用。
- 任务答案只提交一次，答错不重试（时间预算优先留给「做完两个任务」）。
